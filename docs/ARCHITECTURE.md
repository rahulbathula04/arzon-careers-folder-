# Arzon Careers — Engineering Architecture

**Repo scale (2026-07-07):** 577 TS/TSX source files · 135 route files · 276 component files · 116 SQL migrations · 76 public-schema tables · 84 public-schema functions · 65 runtime deps · 24 dev deps.

> This document is the source-of-truth architecture reference. Per-file walkthroughs of all 577 files are impractical in one document — files are grouped by subsystem with representative files named. The **Deep-Dive Index** at the end lists per-module follow-ups you can request.

---

## 0. TL;DR

Arzon Careers is a **deployment-ready career platform** for Indian pharmacy/engineering/degree students: marketing site + Career Engine assessment + tiered paid enrolment + employer hiring console + admin ops surface. It runs on the modern Lovable stack: **TanStack Start v1 (React 19, SSR) on Cloudflare Workers**, with **Supabase (Postgres + Auth + Storage)** and **Razorpay** payments.

## 3. Router & Bootstrap

**`src/router.tsx`** — Router config: `defaultPreload: "intent"`, `defaultPreloadDelay: 50`, `defaultPreloadStaleTime: 30_000` (hover-preload + 30s cache to cut Worker+Postgres load), `scrollRestoration: false` (manual scroll inside `#app-scroll-root`), `defaultErrorComponent` reports throws to `reportSsrError`.

**`src/start.ts`** — Registers `attachSupabaseAuth` as global client `functionMiddleware`. Every `createServerFn` RPC gets `Authorization: Bearer <access_token>` automatically. Without this, every `_authenticated` server fn returns 401.

**`src/routes/__root.tsx` (761 LOC — the largest single file):**

- HTML shell via `HeadContent` + `Scripts`
- Shared `QueryClient` (`staleTime: 60_000`, `refetchOnWindowFocus: false`)
- Sitewide meta / OG / Twitter / JSON-LD (EducationalOrganization + WebSite + SearchAction)
- Reduced-motion + theme boot scripts (pre-hydration)
- Fonts loaded via `<link media="print">` promoted to `media="all"` on load (non-render-blocking)
- Installs GA4, Sentry, SSR error listener, RLS incident interceptor, applyTracking, A/B bucketing, Speculation Rules
- Renders `<Nav>` → `<Outlet>` → `<MobileWhatsAppFAB>` + `<RouteLoader>`

**`src/routes/_authenticated/route.tsx` (the auth gate):**

```
ssr: false,
beforeLoad: async () => {
  const { data, error } = await supabase.auth.getUser();
  if (error || !data.user) throw redirect({ to: "/admin/login" });
  return { user: data.user };
}
```

`ssr: false` because Supabase session lives in `localStorage` — SSR-gating loops on hard refresh. Per-fn `requireSupabaseAuth` re-validates as defence in depth.

## 4. Supabase Integration

Four distinct entry points:

| File                 | Role                                                                                  | Key                    | RLS             |
| -------------------- | ------------------------------------------------------------------------------------- | ---------------------- | --------------- |
| `client.ts`          | Browser + SSR fallback. Lazy `Proxy` so SSR import doesn't crash.                     | Publishable            | Yes (user/anon) |
| `client.server.ts`   | Privileged (`supabaseAdmin`). Imported inside handler bodies via `await import(...)`. | Service role           | **Bypassed**    |
| `auth-middleware.ts` | `requireSupabaseAuth` — validates request bearer, injects `{supabase,userId,claims}`. | Publishable + user JWT | Yes (user)      |
| `auth-attacher.ts`   | Client middleware — attaches bearer from `getSession()` to every serverFn call.       | —                      | —               |

**Enforced by build:**

- Never call a `requireSupabaseAuth` serverFn from a public loader (SSR prerender has no bearer → 401 → build fail).
- `supabaseAdmin` must be imported inside handler bodies in client-reachable `*.functions.ts` files.
- `SUPABASE_SERVICE_ROLE_KEY` never in browser code.

## 6. Coupon / Promotion Flow (End-to-End)

```
User enters code on /enrol/:tier/pay
  → applyEnrolmentCoupon (serverFn)           src/lib/enrolment.functions.ts
      → rpc apply_enrolment_coupon            [SECURITY DEFINER]
          ├─ ei_assert_owner(intent_id, token)
          ├─ idempotent re-apply
          ├─ coupons row + is_active check
          ├─ coupon_tier_prices lookup → override_price_inr
          ├─ per-email cap (max_uses_per_email)
          ├─ ARZONPRIME60 anchor: min(coupon_applied_at) + window
          ├─ discount_pct = round((1 - override/base) * 100)
          └─ UPDATE enrolment_intents → status='coupon_applied'

User clicks Pay
  → createRazorpayOrder (serverFn)            src/lib/razorpay.functions.ts
      ├─ get_enrolment_intent (token-gated)
      ├─ get_cohort_status → gate on effective_locked
      ├─ ARZONPRIME60 re-anchor from earliest coupon_applied_at
      ├─ hard expiry check → structured coupon_expired error
      ├─ POST https://api.razorpay.com/v1/orders (Basic auth)
      └─ rpc attach_razorpay_order

Client opens Razorpay checkout (razorpayCheckout.ts)

Success → POST /api/public/razorpay/verify
  → verify HMAC(order_id|payment_id, key_secret) == signature
  → rpc mark_enrolment_paid_with_payment → provision_enrolment_from_intent

Async webhook → /api/public/razorpay/webhook
  → x-razorpay-signature HMAC verify (timingSafeEqual)
  → webhook_events INSERT (dedupe on unique event_id)
  → dispatch: payment.captured / payment.failed / refund.processed
```

Client-side persistence: `src/lib/arzonPrime60.ts` mirrors expiry to `localStorage` per intent (keeps earliest of stored vs server — reloads can't extend). Only ARZONPRIME60 uses this; other codes use per-intent server expiry.

## 7. Authentication

1. Sign-in on `/admin/login` (or student equivalent) → `supabase.auth.signInWith*`.
2. Session persisted in `localStorage` as `sb-<projectRef>-auth-token`.
3. Nav into `_authenticated/*` → gate's `beforeLoad` → `supabase.auth.getUser()` → redirect to `/admin/login` if none.
4. Every serverFn call → client `attachSupabaseAuth` → `Authorization: Bearer <access_token>`.
5. Server `requireSupabaseAuth` → `supabase.auth.getClaims(token)` → injects `{supabase, userId, claims}`.
6. RLS uses `auth.uid()` + `public.has_role(auth.uid(),'admin')`.

`onAuthStateChange` wired **once** in `__root.tsx`, filtered to `SIGNED_IN`/`SIGNED_OUT`/`USER_UPDATED` (unfiltered would thrash router+cache hourly on `TOKEN_REFRESHED`).

## 12. Security Architecture

- RLS on every user-facing table (76 tables, ~180 policies).
- `has_role` / `has_employer_access` SECURITY DEFINER stable helpers used inside policies to avoid recursion.
- Roles in `user_roles` (never on profile) — prevents privilege escalation.
- Public API endpoints self-guard: HMAC for Razorpay, `x-hook-secret` for cron hooks.
- Prebuild `check:rls` blocks `WITH CHECK (true)` on write policies unless annotated `-- rls-check: allow-true reason: ...`.
- Client cannot supply price — `createEnrolmentIntent` derives from `TIER_META`; `createRazorpayOrder` re-reads from DB via token-gated RPC.
- Coupon anti-tamper: expiry double-checked on order create; ARZONPRIME60 re-anchored to earliest applied_at.
- Webhook replay protection via `webhook_events (provider, event_id)` UNIQUE.
- Correlation IDs on every server error (`serverErrorLog.newCorrelationId`) — surfaced in user error strings.
- `rlsIncidentReporter.ts` intercepts client 401/403 → writes to `rls_incidents` for admin triage.

## 13. Performance Notes

- `defaultPreload: "intent"` + `defaultPreloadStaleTime: 30_000` — hover-preloaded chunks reused for 30s.
- Speculation Rules in `__root.tsx` prerender high-intent links.
- Fonts non-render-blocking via `media="print"` swap.
- DNS-prefetch + preconnect to `<project>.supabase.co`.
- Shared `QueryClient` (`staleTime: 60_000`, no focus refetch).
- Backup pagination with `.range()` avoids PostgREST 1000-row truncation.
- A/B events batched (`eventDedupe.ts`).

**Bottlenecks / debt:**

- `__root.tsx` 761 LOC — extract meta/JSON-LD/boot into `src/lib/rootHead.ts`.
- `enrol.$tier.pay.tsx` 1670 LOC — split further into `components/enrol/pay/*`.
- Admin routes inconsistent: some top-level, some under `_authenticated/`.
- Multiple-`<h1>` offenders: `admin.moments.$id`, `admin.tsx`, `build.$slug`, `enrol.success`, `moments.*`, `build.request`, `employer.console`.

## 16. Suggested Improvements (Impact-Ranked)

1. **Split `enrol.$tier.pay.tsx` (1670 LOC)** into `components/enrol/pay/*`. Biggest maintenance win.
2. **Move top-level `admin.*` routes under `_authenticated/admin.*`** — inconsistent gating hurts auditability (serverFn defence-in-depth already covers it).
3. **Promotion Engine Phase 2** — wire `log_promotion_event` into `apply_enrolment_coupon`, `createRazorpayOrder`, webhook handlers → full lifecycle log with zero client change.
4. **Admin promotions dashboard** at `_authenticated/admin.promotions.tsx` — CRUD campaigns, list active coupons via `v_active_promotions`, charts from `promotion_events`.
5. **Extract root head/JSON-LD** from `__root.tsx` → `src/lib/rootHead.ts` for testability.
6. **Fix multiple-h1 offenders** listed above to unblock heading-hierarchy publish check.
7. **Anti-abuse layer** — disposable email + velocity + IP scoring writing to `promotion_events.meta`. Schema already supports it.
8. **Referral / wallet ledger** — `wallet_ledger` table using the same event stream; no coupon-engine changes needed.
9. **QR redirector** — `/api/public/p/:qr_slug` reading `promotion_attributions.qr_slug` → pay page with auto-applied coupon + attribution stamped.
10. **Audit `.functions.ts` handler-body imports** — convert any top-level `import { supabaseAdmin }` in client-reachable files to inline `await import(...)`.
11. **Bulk-revoke anon/public execute** on the ~10 SECURITY DEFINER helpers flagged by Supabase linter.
12. **Defer boot scripts** in `__root.tsx` where possible.
