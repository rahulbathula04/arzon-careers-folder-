# Arzon Global Brand 3.0

## Position

**Career intelligence for healthcare and life sciences.**

Arzon helps students and early-career professionals understand real roles, assess their readiness, build practical capability, and create evidence they can take into the hiring market.

## Brand promise

**Know the role. Build the skills. Prove the work.**

## Product architecture

- **Arzon Careers**: career discovery and role intelligence.
- **Arzon Assessment**: readiness and career-fit assessment.
- **Arzon Programmes**: role-specific training, projects and mentor review.
- **Arzon Proof**: credentials and evidence of work.
- **Arzon for Employers**: talent discovery and workforce readiness.

## User journey

```
Discover → Assess → Prepare → Prove → Apply
```

Every public page should make the next step obvious.

## Primary user action

**Find my career path**

Secondary actions should be contextual:

- Explore roles
- See programme
- Check my readiness
- View the next step
- Talk to a counsellor

Do not put multiple competing primary CTAs in the same viewport.

## Audience

Primary:
- Pharmacy students and graduates
- Life-science students and graduates
- Healthcare career switchers
- Early-career candidates

Secondary:
- Colleges and placement teams
- Healthcare and life-science employers

## Voice

Arzon should sound:

- clear
- credible
- practical
- calm
- professional
- encouraging

Avoid unexplained internal terminology such as “capability architecture”, “deployment layer”, “operational dimensions”, and “workforce infrastructure” in student-facing copy.

Prefer:

- career
- role
- skills
- work
- evidence
- readiness
- assessment
- project
- pathway
- employer

## Layout principles

1. Mobile-first.
2. One clear heading per section.
3. Short paragraphs.
4. One dominant action per viewport.
5. Cards should contain enough information to choose, not enough to overwhelm.
6. Secondary information belongs below the primary decision.
7. Avoid decorative whitespace that pushes useful content below the fold.
8. Use borders and restrained shadows instead of heavy visual effects.
9. Preserve accessible contrast and visible focus states.
10. Floating contact controls must never cover actionable content.

## Mobile rules

- 16px minimum body text.
- 48px minimum primary action height.
- 16px minimum side padding.
- Compact header.
- Bottom-safe floating controls.
- Avoid horizontal overflow.
- Keep primary action visible without competing sticky controls.

## Core page hierarchy

### Homepage

Hero → Choose your situation → Role explorer → How it works → Evidence → Why Arzon → Assessment → Programmes → Employers → Final action

### Role page

Role → What the work is → Skills → Tools → Eligibility → Employers → Salary context → Preparation → Readiness action

### Programme page

Role outcome → What you will do → Curriculum → Projects → Tools → Assessment → Evidence → Cohort → Application

### Assessment

Goal → Background → Interests → Assessment → Result → Gaps → Recommended pathway → Next action

## Design rule

The interface should answer four questions quickly:

1. Where am I?
2. What is this page for?
3. What should I understand?
4. What should I do next?

If a section does not help answer one of these questions, it needs a clear product reason to exist.
