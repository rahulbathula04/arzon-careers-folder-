# Arzon Target UI — Career Intelligence Product System

## Source of truth

The approved visual reference is the eight-surface journey:

1. Home / acquisition
2. Role intelligence
3. Job-family intelligence
4. Degree pathway
5. Career path
6. Career Engine assessment
7. Career Engine result
8. Programme detail

The implementation must read as one product. A page may change its content and data, but not its fundamental interaction grammar.

## Global shell

- Compact white header.
- Arzon mark at left.
- Primary navigation: Careers, Degrees, Career Engine, Resources.
- Secondary actions: Login and Get My Career Plan.
- Mobile navigation retains the same hierarchy.
- One shared footer.
- One shared container and spacing system.

## Hero grammar

Desktop:

- Two-column visual hero.
- Left: eyebrow, outcome-led H1, concise explanation, primary and secondary action.
- Right: relevant healthcare/life-science image.
- Optional floating evidence/demand card.
- Hero should be visually strong without becoming an advertising billboard.

Mobile:

- Copy first.
- Image immediately after actions.
- No horizontal overflow.
- Primary action remains obvious.

## Evidence strip

Immediately below high-intent heroes:

- Four compact proof items.
- Icon + value + label.
- Values must be supported by existing product/data sources.
- Do not fabricate ratings, employer relationships, placement rates or salary guarantees.

## Context navigation

High-information pages use a compact sticky tab strip:

- Overview
- Job Market / Work
- Skills
- Career Path
- Programme / Next Step

Only include tabs for content actually present on the page.

## Content density

Prefer:

- 3-column role grids on desktop.
- 4-column metric/proof strips.
- Compact cards with one decision per card.
- Short paragraphs.
- Strong section headings.
- Thin borders and restrained shadows.

Avoid:

- Giant empty hero areas.
- Long uninterrupted text.
- Editorial cards that hide the decision.
- Multiple competing primary CTAs.
- Decorative sections with no decision value.

## Role page

Hero → proof strip → tabs → role definition → market context → skills/tools → eligibility → evidence → related roles → preparation CTA.

## Job-family page

Hero → proof strip → market snapshot → role directory → recurring skills → employers → Career Engine CTA.

## Degree page

Hero → proof strip → degree role paths → role comparison → Career Engine CTA.

## Career Engine

Use a product-style two-column assessment surface:

- Left: progress, assessment stages, concise reassurance.
- Right: one question/task at a time.
- Clear selected state.
- Persistent progress.
- One primary Next action.

## Result page

- Result identity at top.
- Large fit/readiness visualization.
- Recommended role.
- Evidence explaining the recommendation.
- Nearby alternatives.
- Career Plan.
- 12-week preparation roadmap.
- Programme CTA only after the learner understands the recommendation.

## Programme page

- Target role and outcome first.
- Hero image.
- Programme proof strip.
- Curriculum and projects.
- Tools.
- Readiness/evidence.
- Fees and enrolment action.
- Counsellor action as secondary support.

## Brand grammar

- Inter-style sans-serif UI.
- Navy #071A4A.
- Blue #2563EB.
- Purple/blue gradient for primary conversion actions.
- White / very light blue-grey surfaces.
- Small radii, thin borders.
- No decorative serif typography on student-facing product surfaces.
- Icons are functional and consistent.
- Photography should show the learner/job context, not generic stock-office scenes.

## Decision principle

Every viewport must answer:

1. Where am I?
2. What is this page about?
3. What evidence should I understand?
4. What should I do next?

The product journey is:

Discover → Explore role → Assess → Understand result → Prepare → Enrol

The programme is never the first decision when the visitor has role uncertainty.
